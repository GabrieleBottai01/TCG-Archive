# Cardtrader as a second (primary) sealed price source — design

**Date:** 2026-07-19
**Status:** approved (brainstorming)
**Scope:** Phase 2, sub-project B. Depends on 2A (English catalogue names) — the English catalogue
name is the bridge into Cardtrader's taxonomy.

## Problem

Sealed valuation currently uses a single free source: the **median of active eBay IT+DE asking
listings** (`liveEbayEstimate`). It works but has known caveats: asking (not sold) prices, thin
samples, and title-matching fragility. Cardtrader is the reference European marketplace for TCG,
with a clean product taxonomy (blueprints) and native EUR prices — a better primary signal for
sealed products. Gabriele approved adding it as a second source, **primary over eBay**.

## Verified facts about the Cardtrader API (2026-07-19)

- Base URL `https://api.cardtrader.com/api/v2`. Auth: header `Authorization: Bearer <JWT>`. The
  token is generated by the account holder in profile settings (API Access); it appears inline in
  the docs page when logged in, i.e. available to a registered user (not only paid sellers). **To
  be confirmed empirically when Gabriele generates it** — if it turns out gated behind a paid plan,
  the feature degrades gracefully (see "Absent token").
- Rate limits: 200 requests / 10s globally; **`GET /marketplace/products` is limited to ~1 call/s**.
- Sealed products are first-class: the glossary lists categories like "Booster Box".
- Endpoints used (all GET, read-only):
  - `GET /games` → `[{ id, name }]` (find Pokémon `game_id`).
  - `GET /expansions` → `[{ id, game_id, code, name }]`.
  - `GET /blueprints/export?expansion_id={id}` → `[{ id, name, expansion_id, category_id, ... }]`.
  - `GET /marketplace/products?blueprint_id={id}` → `{ "<blueprint_id>": [Product, ...] }` where each
    Product carries `price: { cents, currency }`, `quantity`, `bundle_size`, `properties_hash`,
    `graded`, `on_vacation`, `name_en`. Returns the cheapest 25 products.
  - `GET /info` → auth test.

## Design

### 1. Token & configuration

- New Netlify env var `CARDTRADER_JWT` — **server-side only, never committed**. Gabriele generates it.
- **Absent token:** if `CARDTRADER_JWT` is unset (or `GET /info` fails), the Cardtrader source is
  simply inactive and pricing falls back to the eBay estimate. No crash, no error surfaced to the user.

### 2. Cardtrader client — `src/lib/pricing/cardtrader.ts`

Isolated module, mirroring `sealed.ts` / `ebayEstimate.ts`:

- `getPokemonGameId()`, `getExpansions()`, `getBlueprints(expansionId)` — in-memory cache, 24h TTL
  (like the tcgcsv groups/sets cache in `sealed.ts`; export a `__resetCardtraderCache()` for tests).
- `getMarketplace(blueprintId)` → the cheapest 25 products for that blueprint.
- **Pure** `lowestSealedEur(products)` → the **minimum** `price.cents/100` among products that pass:
  `price.currency === 'EUR'` AND `bundle_size === 1` AND `graded === false` AND `on_vacation === false`.
  Returns `{ eur: number | null, sampleSize: number }` (sampleSize = how many products passed the
  filter). Separated from the fetch so it is unit-testable from fixtures (like `estimateFromListings`).
  - Rationale for **minimum**: the lowest available asking price is the conventional "market price"
    on this marketplace. Start simple; if a single under-priced listing proves noisy, refine later
    (documented as a known trade-off, not silently assumed correct).

All calls send the `Authorization: Bearer` header from `CARDTRADER_JWT`. `getMarketplace` callers
must respect the ~1 req/s marketplace limit (see §5 refresh throttling).

### 3. Blueprint resolution — `resolveBlueprintId(englishName)`

The English catalogue name stored on the item (from 2A, e.g. "Paldean Fates Elite Trainer Box") is
the bridge — it contains both the set and the product type, and Cardtrader blueprint names are
English and structured the same way. (`setName` is unreliable — often empty, as observed live.)

1. **Expansion:** among `getExpansions()` (filtered to Pokémon `game_id`), pick the expansion whose
   normalized `name` is a substring of the normalized English name, longest match wins (reuse
   `normalizeQuery` from `sealedGlossary`). E.g. "Paldean Fates" ⊂ "Paldean Fates Elite Trainer Box".
2. **Blueprint:** among `getBlueprints(expansionId)`, match the product against the blueprint names.
   Reuse the product-type vocabulary (`extractProductType` / the glossary) so "Elite Trainer Box" in
   the item maps to the ETB blueprint. Per-expansion sealed blueprints are few, so this is reliable.
   Longest/most-specific name match wins; ties or no match → return null.
3. Returns `number | null`. Null → no Cardtrader mapping → eBay fallback.

### 4. Data model + value integration

Two nullable, additive columns on `Item` (safe migration, like 2A's `priceQuery`):

- `cardtraderBlueprintId Int?` — the stable resolved mapping; set once at pick (or on first
  successful refresh resolution), so later refreshes are direct `getMarketplace` lookups.
- `autoPriceSource String?` — which source produced the currently stored `marketValue`:
  `'cardtrader'` | `'ebay'`. Drives the collection chip. Null for non-auto / pre-existing items.

`PriceResult` (`types.ts`) gains: `origin?: 'cardtrader' | 'ebay'` and
`cardtraderBlueprintId?: number | null` (the id resolved this call, so the write path can persist it).

**Sealed pricing orchestration** (inside the sealed provider, `TcgcsvProvider.fetchPrice`, and shared
by a helper `sealedPrice(input)`):
1. Determine `blueprintId`: use `input.cardtraderBlueprintId` if present, else `resolveBlueprintId(input.name)`.
2. If a `blueprintId` resolves, `getMarketplace` → `lowestSealedEur`. If `eur != null` →
   `{ value: eur, source: 'AUTO', origin: 'cardtrader', cardtraderBlueprintId: blueprintId }`.
3. Else fall back to `liveEbayEstimate(priceQuery ?? name, language)` →
   `{ value: eur, source: 'AUTO', origin: 'ebay', cardtraderBlueprintId: blueprintId /* may be null */ }`.
4. No data anywhere → `null` (value stays MANUAL).

**Precedence for the displayed value** (unchanged top authority): the observatory `effectiveValue`
still substitutes a **STRONG** `euReference` when present. Final order:
**observatory STRONG > Cardtrader (min) > eBay estimate (median) > MANUAL.** (STRONG is rare and
conservative; in practice most items now read Cardtrader.)

**Write paths persist the new fields:**
- `/api/prices/refresh` writes `marketValue`, `marketValueUpdatedAt`, and now `autoPriceSource` +
  `cardtraderBlueprintId` (when newly resolved) from `PriceResult`.
- The add/edit modal stores them on pick (see §5).
- `itemInputSchema` gains `cardtraderBlueprintId` (number, optional nullable) and `autoPriceSource`
  (string, optional nullable). `PlainItem` gains both.

### 5. Estimate endpoint, modal & refresh

- **`/api/sealed/estimate`** returns the Cardtrader-first primary plus the eBay comparison:
  `{ eur, sampleSize, source: 'cardtrader' | 'ebay' | null, cardtraderBlueprintId: number | null,
  ebay: { eur: number | null, sampleSize: number } }`. `eur`/`source` is the primary (Cardtrader if
  available, else eBay); `ebay` is always the eBay median for the modal's comparison line.
- **Modal (`ItemFormModal`):** on pick, store `marketValue` = primary `eur`,
  `marketValueSource` = AUTO (if eur != null), `autoPriceSource` = `source`,
  `cardtraderBlueprintId` = returned id; auto-fill and label the chip
  **"Cardtrader EU · N offerte"** when `source==='cardtrader'`, else "Stima eBay EU · N annunci".
  Show the eBay comparison as a secondary line **only in the modal** (e.g. "eBay: € X · N annunci")
  — never per-row in the collection list (keeps the list to one stored price).
- **Refresh throttling:** Cardtrader `getMarketplace` is ~1 req/s. The refresh worker pool
  (`CONCURRENCY = 5`) must not fire 5 concurrent Cardtrader calls — serialize the Cardtrader
  marketplace step (or gate it to 1 in flight). Expansions/blueprints are cached, so only the
  marketplace call is rate-limited. `log`/note any items skipped by throttling.

### 6. UI chip

- `src/lib/priceSource.ts` gains a `cardtrader` kind (alongside `estimate`/`euReference`), derived
  from `autoPriceSource === 'cardtrader'`. `PriceSourceChip` renders **"Cardtrader EU · N offerte"**
  (green, primary) vs the existing "Stima eBay EU" for the eBay fallback. i18n `it` + `en`.
- The observatory STRONG chip still wins when a STRONG reference exists (unchanged).

## Non-goals (YAGNI)

- Cardtrader in the daily observatory job (stays eBay-only; Cardtrader is on-demand/refresh).
- Manual blueprint picking UI (auto-resolution + stored id only).
- Cardtrader for raw cards (sealed only; raw cards stay TCGdex).
- Buying/cart/inventory endpoints (read-only pricing only).
- Storing the eBay comparison per collection row (modal-only).
- A robust statistical model over Cardtrader listings (start with the filtered minimum).

## Verification

- Unit (pure, from real fixtures): `lowestSealedEur` filtering + minimum; `resolveBlueprintId`
  expansion + blueprint matching (incl. a no-match → null case).
- Live check **with a real `CARDTRADER_JWT`** (mock-vs-live memory): resolve a known sealed product
  (e.g. Paldean Fates ETB) → sane EUR, chip reads Cardtrader; an item Cardtrader can't map → eBay
  fallback with the eBay chip; absent-token → eBay everywhere, no error.
- Migration: additive nullable columns apply cleanly.
